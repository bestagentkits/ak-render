# 3D blocks

`scene-3d` describes a 3D scene as typed data. The compiler inlines one shared
three.js runtime (generated by `pnpm three:generate`, checked by
`pnpm three:check`) only on pages that use a 3D block, so the page stays offline
and deterministic.

```yaml
- type: scene-3d
  title: Edge cluster
  summary: A core router linked to three edge nodes.
  bind: state.part
  objects:
    - { id: base, shape: plane, size: 6, rotation: [-90, 0, 0], tone: neutral }
    - { id: core, label: Core router, shape: icosahedron, position: [0, 1, 0] }
    - { id: rig, shape: group }
    - { id: edge-a, parent: rig, shape: box, position: [2, 0.5, 0] }
  timeline:
    - { target: core, property: rotation, to: [0, 360, 0], duration: 8000 }
```

## What the spec controls

- `objects`: up to 200, nested by `parent` at most 8 levels. Shapes, materials
  and tones are closed vocabularies; vectors are exactly 3 bounded numbers.
- `lighting`: a preset (`studio`, `soft`, `dramatic`, `night`).
- `camera`: position and target; omitted, the compiler frames the scene.
- `timeline`: rotation spins, position and scale ease back and forth.
- `views` + `viewBind`: a state value moves the camera and highlights an object.
- `bind`: picking an object (pointer, keyboard or the object list) writes its id.

There is no shader, script or raw asset input. `shader`, `glsl`, `wgsl`,
`vertexShader`, `fragmentShader` and prototype keys are rejected anywhere in a spec.

## Assets and network

Model files are opt-in through the `models` network capability. The compiler
never fetches a remote URL; only the browser does, and only when
`policy.network.allow` lists `models` (and the host passes any `providers`
list). Allowed model origins open CSP `connect-src`, since glTF loaders fetch
them; images stay in `img-src`. With no `models` origin, `connect-src` stays
`'none'`. There is no wildcard and no `unsafe-eval`.

Local models are inlined by `resolveModelAsset` (`src/assets/model-assets.ts`,
Node only) as data URIs, so the page stays offline:

- Paths resolve against the spec's directory. Absolute, UNC and drive paths,
  `..` escapes (raw, backslashed or percent-encoded) and symlinks or junctions
  that leave it are rejected (`POLICY_VIOLATION`). A missing spec directory has
  its own diagnostic.
- `.glb` or `.gltf` only. A glTF's buffers are `.bin` files or
  `application/octet-stream` data URIs; its images are PNG, JPEG or WebP,
  checked by magic bytes for files and data URIs alike, and any
  `images[].mimeType` must be one of those. KTX2 is refused until a decoder is
  bundled. A GLB must be self-contained.
- `MODEL_ASSET_LIMITS` caps each file (16 MiB) and each page (32 MiB)
  (`SPEC_BOUNDS_ERROR`). Files are read through a descriptor, never more than
  the cap plus one byte.
- `asset.version` must be `"2.0"`. A remote URI inside a glTF passes the same
  `models` gate.
- `extensionsRequired` is checked against `SUPPORTED_GLTF_EXTENSIONS` (the KHR
  and EXT extensions GLTFLoader handles natively). Draco, Meshopt and KTX2
  decoders are not bundled, so such a model fails with a diagnostic that names
  the missing decoders.

`compile` in the CLI and the MCP `render`/`compose` tools inject
`createModelResolver(specDir)` through `RenderOptions.modelResolver`;
`render.ts` itself stays free of Node built-ins. Without a resolver a local
model fails ("needs a compile from a spec file"); a remote one passes through.

### Why no compressed-mesh decoders

Draco and KTX2 (Basis) decoders ship as wasm loaded in workers; Meshopt's fast
path compiles wasm at runtime. Bundling them offline would need
`'wasm-unsafe-eval'` and `worker-src blob:`, which breaks the no-eval boundary.
Authors decompress with `gltf-transform` before compiling instead.

## model-3d

```yaml
- type: model-3d
  id: crate
  summary: A storage crate with a hinged lid.
  src: models/crate.glb        # or .gltf with relative .bin/.png
  bind: state.part             # chosen hotspot id
  clipBind: state.clip         # animation clip name
  variantBind: state.finish    # KHR_materials_variants name
  hotspots:
    - { id: latch, label: Latch, position: [0, 0.55, 0.46] }
```

- Orbit by drag, pan with shift- or right-drag, zoom with wheel or pinch.
  Keys: arrows orbit, shift+arrows pan, `+`/`-` zoom, `Home`/`0` reset,
  `n`/`p` next or previous hotspot.
- The compiler reads clip names, variant names and bounds from the glTF, and
  frames the camera from them. Clip and variant buttons and the numbered hotspot
  list render server-side; reduced motion shows a clip's first pose.
- CSP on a model page: `connect-src data: blob:` plus allowed model origins, and
  `blob:` plus those origins in `img-src`. Other pages keep `connect-src 'none'`.
- States: `static` → `loading` → `ready`, or `error` (load or decoder failure,
  with a message over the plan), or `unsupported` without WebGL 2. Without JS or
  WebGL the `poster` or a compiler-drawn plan (bounds box plus numbered pins)
  and the hotspot list carry the content.
- Fixtures: `fixtures/3d/model-3d-crate.yaml`, models generated by
  `scripts/generate-model-fixtures.mjs` (including a Draco stand-in that must
  fail).

Diagnostics carry the prop's JSON path, the reference the author wrote and a
`details.fix`; a problem inside a glTF also names its `gltfPath` (e.g.
`buffers[0].uri`).

## Fallbacks

The compiler projects every object through the same camera and emits a labelled
SVG plan plus an object list. That is what readers get without JavaScript,
without WebGL 2, in print and in screenshots of the source. With reduced motion
the live scene renders one still frame.

## Runtime

`window.akRender3d` exposes `mountAll`, `unmountAll`, `stats`, `freeze`, `sync` and `ready` for
tests and tooling. Scenes pause offscreen, recover from context loss and
release shared geometry on unmount. `html[data-ak-3d-quality="low|high"]`
overrides the automatic quality profile.

## Export

`ak-render export <spec> --format png|pdf --out <file>` captures the page in a
local browser: `--chromium <path>`, then `AK_RENDER_CHROMIUM`, then an installed
Chrome or Edge, then a Chromium Playwright already manages. Nothing is ever
downloaded. Driving the browser needs the `playwright-core` package, an optional
dependency that installs no browser; without it the export fails with
`driver-unavailable`. The page is served from a virtual origin with zero network
access; relative assets resolve only inside the spec's directory, or the working
directory when the spec comes from stdin.

`--scheme light|dark`, `--width <px>` (default 1440) and `--scale <1-3>`
(device pixel ratio, default 2) set the capture. `--format` alone decides the
bytes written, whatever the file extension. `--timeout <ms>` (at most 300000) is
one budget for the whole export.

Each 3D scene must draw a live WebGL frame. The exporter pins the high-quality
profile, freezes the first settled pose (reduced motion) and checks that every
scene produced a frame, so PNG and PDF carry the real scene. A failure has a
stable code (`usage`, `invalid-input`, `invalid-spec`, `browser-unavailable`, `driver-unavailable`,
`load-failed`, `timeout`, `webgl-unavailable`, `scene-error`, `capture-failed`,
`write-failed`) and leaves `--out` as it was; the static plan is never passed
off as an export. `--json` prints a receipt with bytes, timing, browser version,
WebGL renderer, frame sizes, missing assets and blocked requests. PNG output is
byte-stable on the same machine and GPU; a PDF embeds its creation time, so it
differs on every run.

`ak-render export doctor` lists every browser candidate, the driver, the
browser export would use and its WebGL 2 renderer.
