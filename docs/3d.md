# 3D blocks

`scene-3d` describes a 3D scene as typed data. The compiler inlines one shared
three.js runtime (generated by `pnpm three:generate`, checked by
`pnpm three:check`) only on pages that use a 3D block, so the page stays offline
and deterministic.

```yaml
- type: scene-3d
  title: Edge cluster
  summary: A core router linked to three edge nodes.
  bind: state.part
  objects:
    - { id: base, shape: plane, size: 6, rotation: [-90, 0, 0], tone: neutral }
    - { id: core, label: Core router, shape: icosahedron, position: [0, 1, 0] }
    - { id: rig, shape: group }
    - { id: edge-a, parent: rig, shape: box, position: [2, 0.5, 0] }
  timeline:
    - { target: core, property: rotation, to: [0, 360, 0], duration: 8000 }
```

## What the spec controls

- `objects`: up to 200, nested by `parent` at most 8 levels. Shapes, materials
  and tones are closed vocabularies; vectors are exactly 3 bounded numbers.
- `lighting`: a preset (`studio`, `soft`, `dramatic`, `night`).
- `camera`: position and target; omitted, the compiler frames the scene.
- `timeline`: rotation spins, position and scale ease back and forth.
- `views` + `viewBind`: a state value moves the camera and highlights an object.
- `bind`: picking an object (pointer, keyboard or the object list) writes its id.

There is no shader, script or raw asset input. `shader`, `glsl`, `wgsl`,
`vertexShader`, `fragmentShader` and prototype keys are rejected anywhere in a spec.

## Bars 3D

`bars-3d` draws a categories x series matrix as grouped or stacked bars. The
spec gives only data; the compiler owns the layout, scale, camera and colors.

```yaml
- type: bars-3d
  summary: Operating cash builds while capital spend pulls the stack below zero.
  mode: stacked          # grouped (default): one depth row per series
  unit: ' M'
  bind: state.bar        # the picked bar id, `category/series`
  filterBind: state.flow # a series id shows only that series
  categories: [{ id: q1, label: Q1 }, { id: q2, label: Q2 }]
  series: [{ id: ops, label: Operations }, { id: invest, label: Investing }]
  values: [[42, -12], [38, -46]]   # one row per category, one value per series
```

- Every bar starts at zero. Grouped bars span `[min(0, v), max(0, v)]`; stacked
  positives build up and negatives build down from zero, so a stack ends at the
  category's positive and negative sums. A translucent zero plane and a full-ink
  zero line mark the baseline; ticks are round steps that include zero.
- Up to 100 categories, 12 series and 1,000 bars. `values` must match both lists.
- The legend filters by series: hidden bars collapse to the baseline and the
  rest restack. Filtering eases (about half a second) and bars rise once on load
  only when motion is allowed; with reduced motion every change is immediate,
  and export or print settles any transition before the frame is frozen.
- Series take theme tones in order; past the sixth a tone repeats one shade deeper.
- Without JavaScript or WebGL, and in print, readers get a flat SVG bar chart of
  the same extents and a table of every value (with stack totals). Each table
  value is a button that selects its bar once the runtime runs.
## Assets and network

Model files are opt-in through the `models` network capability. The compiler
never fetches a remote URL; only the browser does, and only when
`policy.network.allow` lists `models` (and the host passes any `providers`
list). Allowed model origins open CSP `connect-src`, since glTF loaders fetch
them; images stay in `img-src`. With no `models` origin, `connect-src` stays
`'none'`. There is no wildcard and no `unsafe-eval`.

Local models are inlined by `resolveModelAsset` (`src/assets/model-assets.ts`,
Node only) as data URIs, so the page stays offline:

- Paths resolve against the spec's directory. Absolute, UNC and drive paths,
  `..` escapes (raw, backslashed or percent-encoded) and symlinks or junctions
  that leave it are rejected (`POLICY_VIOLATION`). A missing spec directory has
  its own diagnostic.
- `.glb` or `.gltf` only. A glTF's buffers are `.bin` files or
  `application/octet-stream` data URIs; its images are PNG, JPEG or WebP,
  checked by magic bytes for files and data URIs alike, and any
  `images[].mimeType` must be one of those. KTX2 is refused until a decoder is
  bundled. A GLB must be self-contained.
- `MODEL_ASSET_LIMITS` caps each file (16 MiB) and each page (32 MiB)
  (`SPEC_BOUNDS_ERROR`). Files are read through a descriptor, never more than
  the cap plus one byte.
- `asset.version` must be `"2.0"`. A remote URI inside a glTF passes the same
  `models` gate.
- `extensionsRequired` is checked against `SUPPORTED_GLTF_EXTENSIONS` (the KHR
  and EXT extensions GLTFLoader handles natively). Draco, Meshopt and KTX2
  decoders are not bundled, so such a model fails with a diagnostic that names
  the missing decoders.

`compile` in the CLI and the MCP `render`/`compose` tools inject
`createModelResolver(specDir)` through `RenderOptions.modelResolver`;
`render.ts` itself stays free of Node built-ins. Without a resolver a local
model fails ("needs a compile from a spec file"); a remote one passes through.

### Why no compressed-mesh decoders

Draco and KTX2 (Basis) decoders ship as wasm loaded in workers; Meshopt's fast
path compiles wasm at runtime. Bundling them offline would need
`'wasm-unsafe-eval'` and `worker-src blob:`, which breaks the no-eval boundary.
Authors decompress with `gltf-transform` before compiling instead.

## model-3d

```yaml
- type: model-3d
  id: crate
  summary: A storage crate with a hinged lid.
  src: models/crate.glb        # or .gltf with relative .bin/.png
  bind: state.part             # chosen hotspot id
  clipBind: state.clip         # animation clip name
  variantBind: state.finish    # KHR_materials_variants name
  hotspots:
    - { id: latch, label: Latch, position: [0, 0.55, 0.46] }
```

- Orbit by drag, pan with shift- or right-drag, zoom with wheel or pinch.
  Keys: arrows orbit, shift+arrows pan, `+`/`-` zoom, `Home`/`0` reset,
  `n`/`p` next or previous hotspot.
- The compiler reads clip names, variant names and bounds from the glTF, and
  frames the camera from them. Clip and variant buttons and the numbered hotspot
  list render server-side; reduced motion shows a clip's first pose. A remote
  model is not read at compile time, so it gets orbit and hotspots but no clip
  or variant controls. Unnamed clips are `animation_<i>`, as GLTFLoader names them.
  The runtime fits the loaded model to the stage's real aspect (projected box
  centred, 5% margin across and 7% down) and refits on resize while at home; an authored
  `camera.position` or `target` is kept. The stage keeps the shared 16:9 (4:3 on
  phones) aspect so model and scene blocks align in a page, so a near-cubic
  model fills by height.
  The wheel zooms only after the stage is clicked or focused (or with Ctrl).
- CSP on a model page: `connect-src data: blob:` plus allowed model origins, and
  `blob:` plus those origins in `img-src`. Other pages keep `connect-src 'none'`.
- States: `static` → `loading` → `ready`, or `error` (load or decoder failure,
  with a message over the plan), or `unsupported` without WebGL 2. Without JS or
  WebGL the `poster` or a compiler-drawn plan (bounds box plus numbered pins)
  and the hotspot list carry the content.
- Fixtures: `fixtures/3d/model-3d-crate.yaml`, models generated by
  `scripts/generate-model-fixtures.mjs` (including a Draco stand-in that must
  fail).

Diagnostics carry the prop's JSON path, the reference the author wrote and a
`details.fix`; a problem inside a glTF also names its `gltfPath` (e.g.
`buffers[0].uri`).

## scatter-3d

`scatter-3d` plots up to 20,000 points on real x/y/z axes. Data is columnar, so
a 20k-point spec stays compact; scalar columns (numbers or strings only) may hold
up to `maxColumnValues` (20,000) entries instead of the usual 200-item list bound.

```yaml
- type: scatter-3d
  title: Fleet load
  summary: Latency, CPU load and memory per host.
  bind: state.point        # a pick writes the point id
  filterBind: state.cluster # a legend click writes the group; "all" clears it
  axes:
    x: { label: Latency, unit: ms }
    y: { label: CPU load, unit: '%', min: 0, max: 100 }
    z: { label: Memory, unit: GB }
    size: { label: Requests, unit: k/s }
  groups:
    - { value: core, tone: accent }
    - { value: edge, tone: success }
  data:
    id: [h1, h2, h3]
    x: [12, 40, 33]
    y: [55, 72, 104]
    z: [8, 16, 12]
    size: [3, 9, 5]
    group: [core, edge, core]
```

- Scales: omitted bounds snap to 1-2-5 ticks around the data; explicit `min`/`max`
  are kept exact and points outside them are clipped (not drawn, flagged in the
  table and counted in the status line).
- Encodings: `group` colours by tone (up to 9 groups, each with a distinct default colour); otherwise `value` with
  `axes.color` uses a sequential info → accent → danger ramp. `size` scales the point radius. Each
  encoding gets a legend.
- Interaction: click or `n`/`p` picks a point; drag with the Brush tool (or
  Shift-drag) brushes a region and fires `brush` with the count; Escape clears.
- Fallback: a full data table lists every point, so no-JS, print and screen
  readers see every value. The SVG poster uses the live camera.
- Rendering is one `Points` draw call with a lit sphere impostor shader.

## Fallbacks

The compiler projects every object through the same camera and emits a labelled
SVG plan plus an object list. That is what readers get without JavaScript,
without WebGL 2, in print and in screenshots of the source. With reduced motion
the live scene renders one still frame. Boxes, including a model's bounds, are
drawn as their camera-facing faces with light shading, so the plan reads as a
solid.

`export3dPosterSvg(spec, { blockId, scheme, labels, modelResolver })` returns
that plan as a standalone, deterministic SVG with its own styles. `scheme` is
`light`, `dark` or `auto` (both palettes, following `prefers-color-scheme`);
`labels: false` drops text for thumbnails. The gallery's 3D cards use it.

## Runtime

`window.akRender3d` exposes `mountAll`, `unmountAll`, `stats`, `freeze`, `sync` and `ready` for
tests and tooling. Scenes pause offscreen, recover from context loss and
release shared geometry on unmount. `html[data-ak-3d-quality="low|high"]`
overrides the automatic quality profile.

## network-3d

`network-3d` draws a node-link graph in 3D. The compiler lays it out at compile
time with a seeded generator, so the same spec gives byte-identical HTML.

```yaml
- type: network-3d
  title: Service mesh
  summary: Eighteen services in four tiers.
  layout: force            # force | hierarchical | radial (radial uses `root`)
  directed: true
  bind: state.service      # picking a node writes its id; the state selects it back
  filterBind: state.tier   # legend chips write a group id ("" shows all)
  groups: [{ id: edge, label: Edge }, { id: core, label: Core }]
  nodes: [{ id: gateway, label: API gateway, group: edge }, { id: auth, group: core }]
  edges: [{ from: gateway, to: auth }]
```

- `nodes` and `edges` take up to 200 entries each. Larger graphs use the compact
  text props: `nodeList` (one `id [group] [label…]` per line) and `edgeList`
  (`from>to` tokens). A graph holds up to 2000 nodes and 4000 links.
- Errors: duplicate node or group ids, an edge or root naming no node, a
  self-link, a node group missing from `groups`. Cycles are allowed.
- A selection lights the node, its links and neighbours and dims the rest; the
  camera flies to it (a jump under reduced motion). `n`/`p` walk nodes, `Enter`
  picks, `Escape` returns home.
- Without JavaScript, in print and in screenshots of the source the block shows
  a static SVG plan and a table of every node with its group, link count and
  neighbours. The table rows carry `data-ak-net-near` while the graph is live.
- One instanced mesh draws every node and two line sets draw every link, so the
  1000-node stress fixture mounts in a handful of draw calls.

## Export

`ak-render export <spec> --format png|pdf --out <file>` captures the page in a
local browser: `--chromium <path>`, then `AK_RENDER_CHROMIUM`, then an installed
Chrome or Edge, then a Chromium Playwright already manages. Nothing is ever
downloaded. Driving the browser needs the `playwright-core` package, an optional
dependency that installs no browser; without it the export fails with
`driver-unavailable`. The page is served from a virtual origin with zero network
access; relative assets resolve only inside the spec's directory, or the working
directory when the spec comes from stdin.

`--scheme light|dark`, `--width <px>` (default 1440) and `--scale <1-3>`
(device pixel ratio, default 2) set the capture. `--format` alone decides the
bytes written, whatever the file extension. `--timeout <ms>` (at most 300000) is
one budget for the whole export.

Each 3D scene must draw a live WebGL frame. The exporter pins the high-quality
profile, freezes the first settled pose (reduced motion) and checks that every
scene produced a frame, so PNG and PDF carry the real scene. A failure has a
stable code (`usage`, `invalid-input`, `invalid-spec`, `browser-unavailable`, `driver-unavailable`,
`load-failed`, `timeout`, `webgl-unavailable`, `scene-error`, `capture-failed`,
`write-failed`) and leaves `--out` as it was; the static plan is never passed
off as an export. `--json` prints a receipt with bytes, timing, browser version,
WebGL renderer, frame sizes, missing assets and blocked requests. PNG output is
byte-stable on the same machine and GPU; a PDF embeds its creation time, so it
differs on every run.

`ak-render export doctor` lists every browser candidate, the driver, the
browser export would use and its WebGL 2 renderer.

## Benchmark

`pnpm bench:3d` measures frame-time p50/p95 (vsync-capped), `renderer.render` time p50/p95, draw calls and triangles (`renderer.info`, not GPU memory), the quality profile and pixel ratio, context loss and restore, a 10-cycle mount/unmount leak check and PNG export reliability for `fixtures/3d/scene-3d-basic.yaml` and `scene-3d-dense.yaml` at 375 and 768 (mobile and touch emulation) and 1440 at 1x and 2x. It fails when draws drift from the committed baseline, [benchmark-3d.md](artifacts/benchmark-3d.md) and `benchmark-3d.json`, which `pnpm bench:3d:update` rewrites with browser, GPU, OS and CPU metadata. It is tagged `@bench` and stays out of ordinary browser runs.

The runtime keeps the last 240 `renderer.render` times per scene for this benchmark (two `performance.now()` calls a frame); it costs no measurable time and is never sent anywhere.
